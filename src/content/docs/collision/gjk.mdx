## 问题：SAT 的候选轴越来越多

上一篇的 SAT 简单直观，但它有两个麻烦：

- **每种形状组合都要单独想候选轴**。多边形与多边形是边法线；多边形与圆还要加一条"最近顶点 → 圆心"；胶囊体、圆角矩形又各有各的特殊轴。形状种类一多，组合数就会爆炸。
- **顶点一多就慢**。两个 n 边形有 2n 条轴，每条轴投影 2n 个顶点，代价是 n² 级别。到了三维，两个盒子之间就有 15 条候选轴。

**GJK**（Gilbert–Johnson–Keerthi，1988）用一个统一的框架解决了这两个问题：它只要求每个形状回答一个问题："沿某个方向，你最远的点在哪里？"多边形、圆、胶囊体、圆角矩形，乃至它们之间的任意组合，都用同一份代码处理。

## 闵可夫斯基差

GJK 的核心是一个巧妙的变换。把 A 中的每一个点减去 B 中的每一个点，得到的点集称为**闵可夫斯基差** A − B：

```
A − B = { a − b | a ∈ A, b ∈ B }
```

两个凸形状的闵可夫斯基差仍然是凸的，而且它有三个性质，正好对应碰撞检测要回答的三个问题：

1. **A 与 B 相交，当且仅当 A − B 包含原点**。相交意味着存在一个点同时属于 A 和 B，即 a = b，也就是 a − b = 0。
2. **A 与 B 之间的距离，等于原点到 A − B 的距离**。
3. **A 与 B 的穿透深度，等于原点到 A − B 边界的最短距离**，那个方向就是最小分离向量。

于是，"两个形状之间的关系"变成了"一个形状与原点之间的关系"。

## 支撑函数

A − B 可能有很多顶点（两个 n 边形的差最多有 2n 个顶点），圆和胶囊体的差更是一条曲线。好在 GJK 从来不需要把它构造出来，只需要它的**支撑函数**：沿方向 d 最远的点。

本文用"若干核心点 + 半径"来描述凸形状：核心点的凸包向外膨胀一个半径。这一种表示就覆盖了 2D 游戏里几乎所有的碰撞形状，Box2D 的 `b2DistanceProxy` 用的也是这种表示。

A − B 的支撑点可以由 A 和 B 各自的支撑点直接算出：A 沿 d 最远的点，减去 B 沿 −d 最远的点。

## GJK：一步步逼近原点

GJK 的想法是：在 A − B 内部维护一个**单纯形**（二维中是一个点、一条线段或一个三角形，顶点都是 A − B 的支撑点），每一步都让它更接近原点：

1. 求单纯形上离原点最近的点 c。
2. 沿 −c 方向（从 c 指向原点）取一个新的支撑点 w。
3. 如果 w 在这个方向上并没有比 c 走得更远，说明 A − B 在这个方向上已经到头了：c 就是 A − B 上离原点最近的点，两个形状**分离**，距离为 |c|。
4. 否则把 w 加入单纯形，再收缩到离原点最近的那部分（一个顶点或一条边）。如果三角形包住了原点，两个形状**相交**。

<CppSnippet file="collision/gjk/gjk.h" region="gjk" mark={['if (dot(w.p - c, normalized(dir_)) <= tol_) return status_ = Status::Separated;', 'if (simplex_.count == 3) return status_ = Status::Intersecting;  // 原点被三角形包住了']} />

"收缩"这一步就是求点到线段、点到三角形的最近点，同时记下最近点由哪些顶点组成（重心坐标）。用不到的顶点被丢掉，单纯形因此永远不超过三个点：

<CppSnippet file="collision/gjk/gjk.h" region="reduce" />

重心坐标还有一个用处：把同样的权重作用在每个支撑点的 a、b 分量上，就得到了两个形状上各自的**最近点**。

## 亲手试一试

<Demo name="gjk" title="GJK 与 EPA" label="图 2.3" caption="左边是两个形状，右边是它们的闵可夫斯基差 A − B，十字是原点。GJK 的每一步：左边两个朱红点是沿搜索方向取到的支撑点，右边的朱红线是单纯形，箭头是下一步的搜索方向。单纯形包住原点后切换到 EPA：赭黄色多边形不断向外扩张，朱红粗线是离原点最近的边。拖动形状移动，拖动空心小圆旋转；round 给 A 加上圆角。" />

几个值得做的小实验：

1. **单步**执行初始状态：GJK 只用两步就让三角形包住了原点，随后 EPA 扩张了五次。左边的红色箭头是最终的分离方向和深度。
2. 把 B 拖开，观察右边：A − B 跟着平移，原点落到了它外面。GJK 结束时，虚线是原点到 A − B 的最短距离，它与左边两个最近点之间的距离完全相等。
3. 旋转 B，注意 A − B 的形状随之改变，但它的顶点永远是"A 的某个顶点减去 B 的某个顶点"。
4. 切换到 **circle** 或 **capsule**，再打开 **round**：A − B 变成了带圆角的形状，同一份 GJK 代码照样工作，只是要多迭代几步。

<Aside type="caution" title="测试发现的错误：原点恰好落在线段上">
最初的实现总是沿 −c 搜索。两个圆相交时，前两个支撑点和原点**恰好在同一条直线上**（都在两个圆心的连线上），原点落在线段上，c 本应是零向量，实际上却是一个由浮点误差决定、方向随机的极小向量。沿它搜索，常常又取回已有的支撑点，GJK 于是误判为"分离，距离 0"。

在 21339 对相交的圆中，有 762 对（3.6%）被误判。修正方法来自 Box2D：单纯形是线段时，搜索方向改用线段的垂线，朝向原点的一侧；原点到这条直线的距离小到可以忽略时，直接判定相交。修正后误判为 0。
</Aside>

## 曲线形状与容差

多边形的 A − B 也是多边形，GJK 在有限步内就能精确停在某个顶点或边上。但圆的 A − B 是曲线，每取一个新的支撑点都只能更接近一点，永远不会恰好"到头"。所以第 3 步的判断需要一个**容差**：新支撑点前进不到 `tol` 就停止。

在 20000 对随机放置的盒子与圆上测量：

| 容差 | GJK 平均迭代 | EPA 平均迭代 | 距离的最大误差 | 深度的最大误差 |
|---|---|---|---|---|
| 0.1 | 2.71 | 4.16 | 0.099 | 0.098 |
| 0.01 | 3.08 | 4.84 | 0.010 | 0.010 |
| 0.001 | 3.42 | 5.92 | 0.001 | 0.001 |
| 0.0001 | 3.76 | 6.28 | 0.0001 | 0.006 |

误差基本等于容差，而且容差每缩小 10 倍只多迭代约 0.35 步，收敛很快。最后一行 EPA 的误差没能跟着缩小，是因为 float 的精度到头了。

## EPA：求穿透深度

GJK 判定相交后，单纯形是一个包住原点的三角形。要求穿透深度，需要找到原点到 A − B **边界**的最近距离。**EPA**（Expanding Polytope Algorithm）从这个三角形出发，把它逐步扩张成 A − B 的近似：

1. 找到多边形上离原点最近的边，记下它的法线 n 和距离 d。
2. 沿 n 取一个新的支撑点 w。
3. 如果 w 在 n 方向上并不比 d 更远，这条边就在 A − B 的真实边界上：d 就是穿透深度，n 就是分离方向。
4. 否则把 w 插入这条边的两个端点之间，回到第 1 步。

<CppSnippet file="collision/gjk/gjk.h" region="epa" />

<Aside type="note" title="为什么法线就是推开 B 的方向">
把 B 平移 t，闵可夫斯基差就变成 (A − B) − t。它不再包含原点，当且仅当 t 落在 A − B 之外。所以让 B 移动最短距离而分开，就是让 t 越过 A − B 上离原点最近的边界点，也就是 n·d。
</Aside>

把 GJK 和 EPA 合起来，就是一个完整的查询：分离时给出距离和两个最近点，相交时给出深度、方向和接触点。

## 实测：GJK 与 SAT

在随机放置、随机旋转的正多边形对上，测量判断是否相交（左）和求最小分离向量（右）的耗时：

| 顶点数 | SAT（30% / 全部相交） | GJK（30% / 全部相交） | SAT 求 MTV | GJK + EPA | EPA 迭代 |
|---|---|---|---|---|---|
| 4 | 36 / 49 ns | 86 / 60 ns | 57 ns | 309 ns | 3.6 |
| 8 | 82 / 198 ns | 99 / 74 ns | 208 ns | 469 ns | 6.0 |
| 16 | 323 / 816 ns | 155 / 105 ns | 872 ns | 799 ns | 8.6 |
| 32 | 1316 / 3313 ns | 197 / 179 ns | 3626 ns | 1384 ns | 11.2 |
| 64 | 4881 / 15095 ns | 426 / 427 ns | 16542 ns | 3656 ns | 13.7 |

几点观察：

- **GJK 的迭代次数几乎不随顶点数变化**：无论 4 边形还是 64 边形，平均都是 1.9~2.0 次。每次迭代只需一次线性的支撑函数调用，所以总代价随顶点数线性增长，而 SAT 是平方增长。
- **盒子这样的简单形状，SAT 更快**：4 个顶点时 SAT 只需检查 8 条轴，GJK 维护单纯形的固定开销反而更大。8 个顶点左右两者打平，之后 GJK 迅速拉开差距，64 个顶点时快了 35 倍。
- **EPA 比 GJK 贵得多**：它的迭代次数随顶点数增长，还要在动态数组中插入顶点。求穿透深度时，16 个顶点以下 SAT 更划算。

这也解释了实际引擎的选择：Box2D 用 GJK 计算形状间的距离（连续碰撞检测需要它），而多边形之间的接触仍然用 SAT 风格的方法。三维引擎（Bullet、PhysX）面对的是凸包和各种曲面，基本以 GJK/EPA 为主。

<Aside type="note" title="测试环境">
Apple M3，Apple clang 21，`-O2`，每组 20000 对，取 11 次中的最快值。代码在 `cpp/collision/gjk/gjk_bench.cpp`。
</Aside>

## 常见陷阱

| 问题 | 原因 | 解决 |
|---|---|---|
| 两个圆明明重叠却判定为分离 | 原点落在单纯形的线段上，−c 的方向由浮点误差决定 | 线段情况用垂线作为搜索方向；原点离直线足够近时直接判定相交 |
| 圆、胶囊体上 GJK 不停地迭代 | 曲线形状上永远"还能再前进一点" | 设置容差和最大迭代次数 |
| 接触时 EPA 崩溃或返回 NaN | 两个形状恰好接触，GJK 只留下 1~2 个点 | 先补成三角形；跳过长度为零的边 |
| 穿透深度时大时小 | EPA 的多边形朝向不一致，算出的法线朝内 | 构造时统一顶点顺序 |
| 物体堆叠时抖动 | GJK/EPA 只给出一个接触点 | 需要稳定堆叠时，用上一篇的参考边裁剪求出两个接触点 |

## 在游戏中的应用

- **距离查询**：AI 判断离掩体还有多远、摄像机与墙之间还有多少空间、角色是否"贴着"墙，都可以直接用 GJK 求凸形状之间的距离。
- **连续碰撞检测**：2.9 中的保守前进法反复调用 GJK 求距离，估算两个物体最早什么时候会碰上。
- **三维物理引擎**：凸包、圆柱、圆锥、胶囊体之间的碰撞，几乎都靠 GJK/EPA，因为只有支撑函数能统一处理这么多形状。
- **形状投射**：沿一个方向扫过一个形状，看它最先碰到什么（比 2.1 的射线检测"粗"一些），也可以基于 GJK 实现。

## 练习

1. **核心 + 半径**：Box2D 不把半径放进支撑函数，而是只对核心点做 GJK，得到核心之间的距离后再减去两个半径。这样核心总是多边形，GJK 可以精确停止。实现这种做法，比较它与本文版本在圆、胶囊体上的迭代次数。
2. **热启动**：物体每帧只移动一点，上一帧最后的单纯形很可能仍然接近答案。把它的顶点编号（A 和 B 上各是第几个点）缓存下来，下一帧从它开始迭代，统计迭代次数的变化。
3. **爬山法求支撑点**：顶点很多的凸多边形，可以从上一次的支撑顶点出发，沿着边往点积更大的方向走，而不是遍历所有顶点。实现它，再跑一次 64 边形的测试。
4. 把 GJK 推广到三维：单纯形最多有四个点（四面体），收缩时多了"原点在哪个面的区域"的判断。
