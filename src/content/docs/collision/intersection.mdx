## 卷二导读：一次碰撞检测要经过哪些步骤

游戏里每一帧都要回答"谁和谁碰到了"。物体一多，两两检查就会变成 n² 的灾难，所以物理引擎通常把这个问题拆成三步：

| 阶段 | 做什么 | 本卷章节 |
|---|---|---|
| 宽相（broad phase） | 用很粗糙但很快的方法，排除绝大多数不可能相碰的物体对 | 2.4 ~ 2.6 |
| 窄相（narrow phase） | 对剩下的物体对做精确的相交测试，并算出接触信息 | 2.1 ~ 2.3 |
| 响应（response） | 根据接触信息把物体分开，调整速度 | 2.7 ~ 2.9 |

这一篇是窄相的起点：三种最简单、也最常用的形状。它们简单到几乎每个游戏都会直接用，复杂的形状也往往先套一个盒子或圆做初步判断。

## 问题：最常见的三个问题

- **两个东西重叠了吗？** 玩家碰到了金币、敌人进入了警戒范围、子弹打中了箱子。
- **重叠了多少，往哪边分开？** 角色撞到墙上，需要被推回去，而且推回的距离要恰好。
- **一条射线最先碰到什么？** 激光、即时命中的武器、鼠标点选、AI 的视线检查。

## 三种形状

<CppSnippet file="collision/intersect/intersect.h" region="shapes" />

**AABB**（Axis-Aligned Bounding Box，轴对齐包围盒）是边与坐标轴平行的矩形，用左上角和右下角两个点表示。它不能旋转，但正因为如此，所有测试都可以拆成 x、y 两个方向分别处理，非常快。

## 相交判断

<CppSnippet file="collision/intersect/intersect.h" region="overlap" />

三个测试各有一个值得记住的思路：

- **AABB 与 AABB**：两个盒子重叠，当且仅当它们在 x 方向**和** y 方向上都有重叠。只要有一个方向分开了，它们就不相交。这个"找一个分开的方向"的想法，下一篇会推广成[分离轴定理](/collision/sat/)。
- **圆与圆**：圆心距离小于半径之和。比较**距离的平方**，可以省掉一次开方。
- **圆与 AABB**：先找到盒子上离圆心最近的点，只需要把圆心的每个坐标**夹**到盒子的范围内，再判断这个点是否在圆里。

<Aside type="note" title="小于，还是小于等于">
本文的实现用严格小于：两个形状只是边缘接触时，不算重叠。这个选择很重要：角色站在地面上时，它的盒子底边正好贴着地面的顶边，如果这也算"重叠"，物理系统就会不停地把它往上推。
</Aside>

## 亲手试一试

<Demo name="intersect" title="基础相交测试" label="图 2.1" caption="拖动盒子 A、B 和圆 C、D。重叠的形状描红，红色箭头是最小分离向量，数字是穿透深度。拖动射线的起点（实心圆）和方向柄（空心圆，t = 1 的位置）。slabs 显示盒子 A 的两条板以及射线在其中的参数区间；separate 沿最小分离向量把重叠的形状推开。" />

几个值得做的小实验：

1. 把圆 D 拖到盒子 B 的角上，观察分离向量：它从盒子的角点指向圆心，而不是沿着某条边。
2. 把圆 C 的圆心完全拖进盒子 A 里面。分离向量变成垂直于最近的那条边，长度是"圆心到这条边的距离 + 半径"。
3. 打开 **slabs**，让射线穿过盒子 A，对比两段区间：射线先进入 x 板、后进入 y 板（或者反过来），两段区间重叠的部分就是射线在盒子里的部分。
4. 让射线与 x 轴平行地擦过盒子的上边，看看它什么时候算命中。

## 不只是"是否重叠"：接触信息

知道两个物体重叠还不够。把角色从墙里推出来，需要知道**往哪个方向推、推多远**。这就是**最小分离向量**（Minimum Translation Vector，MTV）：沿着它移动，两个形状恰好分开，而且移动的距离最短。

<CppSnippet file="collision/intersect/intersect.h" region="contact" />

<Aside type="caution" title="一个常见的错误：重叠长度不等于穿透深度">
很多教程计算 AABB 的穿透深度时，用的是两个区间的**重叠长度** `min(a.max, b.max) - max(a.min, b.min)`。当一个盒子在某个方向上**包含**了另一个盒子时，这是错的：比如一个窄盒子插在一个宽盒子的正中间，重叠长度只是窄盒子的宽度，但要把它推出去，必须一直推到宽盒子的边外。

本文最初的实现就犯了这个错误。单元测试检查"沿 MTV 移动后是否真的分开"，5000 对随机盒子里有 383 对（约 7.7%）没有分开。正确的做法是分别计算"往正方向推出"和"往负方向推出"的距离，取较小的那个。
</Aside>

圆与盒子的接触分两种情况。圆心在盒子外时，分离方向就是"最近点 → 圆心"；圆心已经进入盒子内部时，最近点就是圆心自己，方向无从谈起，这时改为找最近的一条边，从那里推出去。

## 射线检测

### 射线与 AABB：slab 法

一个 AABB 可以看成两条"板"（slab）的交集：一条是 `min.x ≤ x ≤ max.x` 的竖条，一条是 `min.y ≤ y ≤ max.y` 的横条。

射线 `origin + t·dir` 穿过每条板时，都对应一段参数区间 `[t进入, t离开]`。射线在盒子里，当且仅当它同时在两条板里，也就是**两段区间的交集**。交集的起点，就是射线进入盒子的位置；最后进入的那条板，决定了命中的是哪个面。

<CppSnippet file="collision/intersect/intersect.h" region="raycast" mark={['if (tMin > tMax) return std::nullopt;  // 两个区间不再重叠']} />

<Aside type="tip" title="除以零">
射线与某条板平行时，`dir` 的这个分量是 0。本文显式处理了这种情况。很多高性能实现会利用 IEEE 浮点数的规则：`1 / 0 = ∞`，不做判断也能得到正确的区间；但当射线起点恰好落在板的边界上时，`0 × ∞` 会产生 NaN，需要额外小心。
</Aside>

### 射线与圆

把射线方程代入圆的方程 `|p - center|² = r²`，得到一个关于 t 的一元二次方程。判别式小于 0，说明射线所在的直线与圆不相交；否则较小的根就是进入圆的位置。

注意 `dir` 不要求是单位向量，t 以 `dir` 的长度为单位。演示里方向柄所在的位置是 t = 1。这很方便：用"起点到终点"作为 `dir`，`t ≤ 1` 就表示命中点在线段上，同一套代码就可以做线段检测。

## 常见陷阱

| 问题 | 原因 | 解决 |
|---|---|---|
| 角色站在地面上不停抖动 | 边缘接触也算作重叠 | 相交判断用严格小于；或者给接触留一个很小的容差 |
| 推出墙后又陷进另一面墙 | AABB 穿透深度用了重叠长度 | 分别计算两个方向的推出距离，取较小者 |
| 射线检测偶尔返回 NaN | 射线与板平行，起点又恰好在板的边界上 | 显式处理平行的情况 |
| 射线起点在物体内部时行为奇怪 | 不同实现约定不同：有的返回 t = 0，有的返回离开的位置 | 明确约定；本文返回 t = 0、法线为零 |
| 高速子弹穿过薄墙 | 每帧只检查一次位置，两帧之间直接越过了墙 | 用射线检测上一帧到这一帧的线段，见 2.9 |
| 大地图上碰撞判断出错 | 坐标很大时 float 精度不够 | 以玩家附近为原点做相对坐标，或使用 double |

## 在游戏中的应用

- **触发区域**：存档点、陷阱、剧情触发器，几乎都是 AABB 或圆。
- **平台跳跃的地面检测**：从角色脚下向下发射两三条很短的射线，判断是否站在地面上，以及地面的法线（斜坡）。
- **即时命中武器与激光**：一条射线，找最近的命中。
- **鼠标点选**：把屏幕坐标转换成世界坐标，判断落在哪个物体的包围盒里；3D 中则是从摄像机发出一条射线。
- **AI 的视线检查**：从敌人眼睛向玩家发射射线，中间如果先命中了墙，就看不见。0.2 的视野锥判断加上这一步，就是完整的"能否看见"。

## 练习

1. 实现线段与 AABB 的相交测试，只需要调用 `raycast` 并传入合适的 `tMax`。
2. **移动的盒子**：盒子 A 这一帧要移动 `v`，它会不会撞上静止的盒子 B？提示：把 B 向四周扩大 A 的半宽和半高，再从 A 的中心沿 `v` 发射一条射线。这就是 2.9 连续碰撞检测的基础。
3. 实现"胶囊"（两端是半圆的线段）与圆的相交测试。提示：找线段上离圆心最近的点。
4. 实现射线与凸多边形的相交测试，思路与 slab 法相同：每条边定义一个半平面。
