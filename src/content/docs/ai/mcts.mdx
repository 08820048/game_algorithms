## 问题：写不出估值函数怎么办

[上一篇](/ai/minimax/)的实测里，一个只数"窗口"的简单估值，比多搜 6 层还值钱。反过来说，Alpha-Beta 的棋力很大程度上取决于估值函数，而估值函数并不总是好写：

- 围棋的局面价值取决于整盘棋的死活和地域，几十年里没人写出可靠的估值函数，每步 200 多种着法也让 Alpha-Beta 搜不深。
- 一款新设计的卡牌游戏或回合制战术游戏，规则还在频繁调整，每改一次规则，估值函数就要重新调。
- 有些游戏的局面很难"看出"好坏，只有下到最后才知道。

**蒙特卡洛树搜索**（Monte Carlo Tree Search，MCTS）换了一个思路：不去估计局面有多好，而是**从这个局面开始随机下很多盘，看看赢了多少**。它只需要知道规则（有哪些着法、谁赢了），不需要任何关于"好棋"的知识。2006 年前后，Rémi Coulom 和 Kocsis、Szepesvári 的工作让它在围棋上取得突破，十年后的 AlphaGo 也建立在它之上。

## 随机对局作为估值

先看最朴素的做法：对每个着法，随机下 N 盘到终局，选胜率最高的着法。

在井字棋上，双方都完全随机地走，先手获胜的概率是 58.5%，后手 28.8%，和棋 12.7%（逐个分支加权求和得到的精确值）。可是双方都不犯错时，井字棋是和棋。随机对局的胜率告诉我们的是"如果接下来双方都乱下，谁更占便宜"，而不是"双方都下得好时谁赢"。

问题出在对手身上：随机对局假设对手也在乱下。一个着法也许有 90% 的随机对局都赢了，但只要对方有一步正确的回应就能翻盘，随机模拟很可能看不到这一步。要解决这个问题，就要让对手的着法也越来越"认真"：对方的每个回应也统计胜率，**对方会选对他最有利的回应**。这样一层一层地展开，就成了一棵树。

## 在探索和利用之间平衡

树中的每个节点都面临同一个问题：接下来这次模拟，走哪个子节点？

- 一直走目前胜率最高的（**利用**）：如果它只是运气好，另一个着法其实更好，就永远发现不了。
- 平均地试所有着法（**探索**）：大量模拟浪费在明显很差的着法上。

这正是"多臂老虎机"问题：几台老虎机的中奖率未知，怎样分配有限的硬币，才能赢得最多？Auer 等人在 2002 年分析了 **UCB1** 公式：选择使下式最大的那台：

```
平均收益 + c · sqrt( ln(总次数) / 这台的次数 )
```

第一项是利用：胜率高的优先。第二项是探索：试得越少，这一项越大，迟早会被选上；但它增长得很慢（对数），差的着法被试的次数越来越少。Kocsis 和 Szepesvári 在 2006 年把 UCB1 用在树的每个节点上，称为 **UCT**，并证明了只要模拟次数足够多，它选出的着法会收敛到 Minimax 的最优着法。

## 四个阶段

每一次迭代都从根出发，走四步：

<CppSnippet file="ai/mcts/mcts.h" region="node" />

**1. 选择**：从根出发，按 UCB 一路选子节点，直到一个还没被访问过的新节点（或者终局）。没访问过的子节点优先，相当于 UCB 为无穷大。

<CppSnippet file="ai/mcts/mcts.h" region="select" />

**2. 扩展**：经过一个已经被模拟过一次、但还没有子节点的节点时，为它创建全部子节点。这里一次创建全部子节点，每个都是"未访问"的状态；有的实现每次只创建一个，效果相同。

<CppSnippet file="ai/mcts/mcts.h" region="expand" />

**3. 模拟**：从新节点开始随机走到终局。

<CppSnippet file="ai/mcts/mcts.h" region="simulate" />

**4. 回传**：沿路径往回，每个节点的访问次数加 1，累加收益。

<CppSnippet file="ai/mcts/mcts.h" region="backprop" />

有两个细节需要注意：

- **收益站在谁的视角**。每个节点记录的是"走到这个节点的那一方"的收益，父节点挑选子节点时直接比较平均收益就行。回传时每往上一层，收益换成对方的视角：`r → 1 − r`。这一步写错，AI 会专挑对手最喜欢的着法，而且代码不会报错。
- **最后选哪个着法**。通常选**访问次数最多**的，而不是平均收益最高的。访问次数少的着法，平均收益的波动很大；访问次数多，说明 UCB 反复确认过它好。

## 实测

### 收敛：井字棋的全部局面

在井字棋全部 4,520 个没有结束的局面上运行 MCTS，看选出的着法是否保持局面的博弈论结果（能赢的局面仍然能赢，能和的局面不会输）：

| 迭代次数 | c = 0.25 | c = 0.5 | c = 1 | c = 1.4 | c = 2 | c = 4 |
|---|---|---|---|---|---|---|
| 10 | 90.9% | 91.0% | 90.5% | 90.8% | 90.7% | 90.3% |
| 30 | 95.0% | 95.9% | 96.2% | 96.1% | 95.3% | 94.6% |
| 100 | 98.0% | 98.7% | 98.3% | 98.0% | 97.7% | 97.3% |
| 300 | 99.3% | 99.8% | 99.5% | 99.2% | 99.1% | 98.6% |
| 1000 | 99.5% | 99.96% | 100% | 99.9% | 99.7% | 99.4% |
| 3000 | 99.85% | 100% | 100% | 100% | 100% | 99.6% |

10 次迭代就有 91%，这并不说明 MCTS 很厉害：很多局面里大部分着法都不改变结果。值得注意的是两端：c 太小（0.25）时，偶尔因为前几次模拟运气不好就再也不回头，3000 次迭代仍有 0.15% 的错误；c 太大（4）时，迭代都花在探索差的着法上，收敛最慢。

### 探索常数

在四子棋上，用不同的 c 与 c = 1.4 对下（每方 10,000 次迭代，随机模拟，49 种两步开局 × 先后手 × 2 轮 = 196 局）：

| c | 0.1 | 0.25 | 0.5 | 0.7 | 1.0 | 2.0 | 4.0 |
|---|---|---|---|---|---|---|---|
| 对 c = 1.4 的得分率 | 15.1% | 43.1% | **68.9%** | 63.3% | 54.3% | 44.6% | 20.2% |

教科书常写 c = √2 ≈ 1.4，这来自 UCB1 的理论分析（收益在 [0, 1] 之间时的遗憾上界）。实际上 0.5~0.7 明显更强。理论值保证的是"最坏情况下不会太差"，而在实际的博弈树中，大部分着法确实很差，少探索一些更划算。c 是 MCTS 最需要调的参数，最佳值取决于游戏和迭代次数。

### 速度

四子棋从空棋盘开始，随机模拟每次迭代约 0.2~0.3 μs（每次迭代都包括一盘下到终局的随机对局），10 万次迭代约 30 ms，生成约 21 万个节点，最深处 11 层。启发式模拟每步都要检查"能不能赢、要不要堵"，每次迭代约 0.6 μs，是随机模拟的 2~3 倍；到了中局，模拟变短，差距缩小到 1.3~1.5 倍。

### 启发式模拟

完全随机的模拟有一个明显的缺陷：一方已经有三子连线，另一方随机走，有 6/7 的概率不去堵。这样的模拟结果和真实的局面价值差得很远。只加一条规则，"能赢就赢，对方要赢就堵"：

| 对局（196 局） | 启发式一方得分 | 每步用时 |
|---|---|---|
| 启发式 1,000 次 对 随机 1,000 次 | 64.3% | 0.29 / 0.17 ms |
| 启发式 10,000 次 对 随机 10,000 次 | 63.8% | 3.0 / 2.1 ms |
| 启发式 100,000 次 对 随机 100,000 次 | 73.7% | 33 / 26 ms |
| 启发式 3,000 次 对 随机 10,000 次 | 50.8% | 0.95 / 2.3 ms |
| 启发式 30,000 次 对 随机 100,000 次 | 58.9% | 9.0 / 25 ms |

启发式模拟只用随机模拟一半不到的时间，就能下成平手或者更好。这条规则本身就是一点点"游戏知识"：MCTS 不需要估值函数，但给模拟加一点知识，收益往往很大。不过模拟策略也不是越强越好，太"聪明"的确定性策略会让模拟结果有系统性偏差，这是 MCTS 研究中的一个经典问题。

### 与 Alpha-Beta 对局

对手是上一篇完整的 Alpha-Beta（剪枝、排序、置换表、迭代加深，带窗口估值）。每组 196 局，表中是 MCTS 一方的得分率和双方每步的平均用时：

| MCTS | 对手 | MCTS 得分 | 每步用时（MCTS / Alpha-Beta） |
|---|---|---|---|
| 随机模拟 1,000 次 | 2 层 | 50.3% | 0.18 / 0.18 ms |
| 随机模拟 1,000 次 | 8 层 | 20.9% | 0.18 / 0.71 ms |
| 随机模拟 10,000 次 | 4 层 | 67.6% | 1.9 / 0.18 ms |
| 随机模拟 10,000 次 | 8 层 | 33.7% | 2.0 / 0.63 ms |
| 随机模拟 10,000 次 | 10 层 | 29.1% | 1.9 / 1.9 ms |
| 随机模拟 100,000 次 | 8 层 | 66.1% | 24 / 0.67 ms |
| 随机模拟 100,000 次 | 12 层 | 53.1% | 24 / 8.5 ms |
| 启发式模拟 10,000 次 | 8 层 | 64.0% | 2.6 / 0.60 ms |
| 启发式模拟 30,000 次，c = 0.5 | 12 层 | **71.2%** | 9.3 / 8.4 ms |

- **用时相同时，"纯"MCTS 打不过 Alpha-Beta**。每步约 1.9 ms 时，随机模拟的 MCTS 对 10 层的 Alpha-Beta 只得 29%；MCTS 用将近 3 倍的时间，才与 12 层打平。Alpha-Beta 有一个人写的估值函数，MCTS 什么知识都没有，这个结果并不意外。
- **一点点知识就能翻转局面**。启发式模拟（能赢就赢、该堵就堵）加上调过的探索常数 c = 0.5，用时相当（9.3 对 8.4 ms）时，对 12 层的 Alpha-Beta 得分 71%。两处改动加起来不到十行代码。
- 反过来，Alpha-Beta 的估值函数还有很大的改进空间（上一篇的练习 4），这里的比较只说明两者在"同样简单的知识"下各自能到什么水平，不能据此判断哪个算法更强。


### 浅层陷阱

MCTS 有一个有名的弱点（Ramanujan、Sabharwal、Selman，2010）：**浅层陷阱**。某个着法看起来不错，随机模拟的胜率也不低，但对方有一个强制获胜的回应序列。Alpha-Beta 搜到那个深度就一定能发现；MCTS 要等到恰好模拟到那条路线足够多次，才会意识到。国际象棋中这种陷阱遍地都是，这被认为是 MCTS 长期下不好国际象棋的原因之一。

我从随机局面中挑出这样的局面：局面本身在 7 层内没有强制的胜负；有些着法会让对方在恰好 k 步内强制获胜（k = 1、3、5），其余着法是安全的。每种 k 各 200 个局面：

| 走法 | 陷阱 1 步 | 陷阱 3 步 | 陷阱 5 步 |
|---|---|---|---|
| 平均有几个着法是陷阱（共约 7 个） | 5.7 | 2.9 | 2.0 |
| 随机走 | 87.5% | 46.5% | 25.5% |
| MCTS 随机模拟 1,000 次 | 0.5% | 1.5% | 6.5% |
| MCTS 随机模拟 10,000 次 | 0% | 0% | 3.0% |
| MCTS 随机模拟 100,000 次 | 0% | 0% | 0% |
| MCTS 启发式模拟 1,000 次 | 0.5% | 1.0% | 4.5% |
| MCTS 启发式模拟 10,000 次 | 0% | 0% | 1.5% |
| Alpha-Beta 2 层 | 0% | 6.0% | 8.5% |
| Alpha-Beta 4 层 | 0% | 0% | 2.5% |
| Alpha-Beta 6 层 | 0% | 0% | 0% |

表中是掉进陷阱的比例。Alpha-Beta 的表现完全符合预期：搜 k+1 层以上就不会掉进 k 步的陷阱，搜不到就看运气。MCTS 越深的陷阱越容易掉进去，1,000 次迭代时 5 步陷阱有 6.5%，需要 10 万次迭代才完全避开。

不过在四子棋上，这个弱点并不严重：MCTS 1,000 次迭代（约 0.2 ms）掉进陷阱的比例，与 Alpha-Beta 2~4 层相当。四子棋每步只有 7 种着法，强制获胜的路线很窄，模拟很快就能覆盖到。在分支更多、陷阱更深的游戏中，差距会大得多。

<Aside type="note" title="测试环境">
Apple M3，Apple clang 21，`-O2`。测量时机器上有其他负载（平均负载 3~5），用时有 10%~30% 的波动。对局每组 196 局，得分率的标准误差约 3.5 个百分点，相差 5 个百分点以内的结果不要太当真。代码在 `cpp/ai/mcts/mcts_bench.cpp`。
</Aside>

## 测试

MCTS 是随机算法，"与暴力算法逐位相同"不再适用，测试换成了几类可以精确检查的性质：

- **树的统计量精确守恒**。每个展开过的节点（根除外）的访问次数 = 1（它自己第一次被模拟）+ 子节点访问次数之和；它的收益 = 第一次模拟的收益（0、0.5 或 1）+ 每个子节点的"访问次数 − 收益"之和（子节点的收益换成这一方的视角）。收益都是 0.5 的倍数，用 double 精确表示，可以用 `==` 比较。终局节点的收益 = 访问次数 × 终局收益。60 棵随机的搜索树，25,673 个节点全部满足。
- **UCB 选择与暴力计算一致**：对每个展开过的节点重新算一遍所有子节点的 UCB 取最大值，与 `selectChild` 相同。
- **随机模拟的分布正确**：井字棋空棋盘的 40 万次随机模拟，平均收益与逐个分支加权求和的精确值相差 0.2 个标准差。
- **启发式模拟**：能一步获胜的局面一定获胜，否则对方能一步获胜时一定堵住。
- **收敛**：井字棋全部 4,520 个局面上，3,000 次迭代选出的着法都保持了局面的博弈论结果。

我故意把实现改坏了 10 处来检验测试，比如回传时不翻转收益、UCB 除以父节点的访问次数、模拟的奇偶算反、和棋算作胜利、启发式模拟从不堵。第一轮有 2 处没有被发现：

- **最终按平均收益而不是访问次数选着法**：这本身也是一种常见的做法，3,000 次迭代时两种选法在井字棋上的结果一样。我补了一项检查，明确要求返回访问次数最多的子节点。
- **删掉"遇到新节点就停止选择"的判断**：结果完全不变。原来我在循环里写了两处同样的判断，删掉一处，另一处照样起作用。这是一个等价变异，它暴露的是冗余代码。我删掉了多余的那处。

补上之后 10 处全部被发现。

## 与其他方法的关系

- **Alpha-Beta**：两者是互补的。有好的估值函数、分支不多、陷阱多（国际象棋）时，Alpha-Beta 更强；没有估值函数、分支很多（围棋、复杂的卡牌和策略游戏）时，MCTS 更实用。MCTS 还有一个工程上的优点：随时可以停下来给出当前最好的着法，用时可以精确控制。
- **AlphaGo 与 AlphaZero**：用神经网络代替随机模拟（价值网络估计胜率），并用策略网络给每个着法一个先验概率，加进 UCB 公式（PUCT）。树搜索的框架和本文完全相同。
- **非完全信息与随机因素**：卡牌游戏看不到对方的手牌。常见做法是"确定化"：按已知信息随机生成对方可能的手牌，在每种可能上分别搜索，或者让整棵树共享（Information Set MCTS）。骰子这类随机因素可以在模拟中直接随机。
- **效用 AI 与 GOAP**：MCTS 也可以用来规划单个角色的行动序列，"对手"换成环境的随机性即可。

| 问题 | 原因 | 解决 |
|---|---|---|
| AI 专挑对手最喜欢的着法 | 回传时没有翻转收益，或者收益站错了视角 | 明确每个节点的收益站在谁一方；写一个"一步就能赢"的测试 |
| 明显该堵的不堵 | 迭代太少；随机模拟里对方经常"忘了"赢 | 增加迭代；启发式模拟（能赢就赢、该堵就堵） |
| 最终选了一个只访问过几次的着法 | 按平均收益选择 | 按访问次数选择 |
| 很快锁定一个着法，再也不回头 | c 太小 | 调大 c；0.5~1.5 之间实测选择 |
| 迭代都浪费在烂着法上 | c 太大 | 调小 c |
| 内存不断增长 | 每次迭代都新增节点 | 节点池按局面复用；限制树的大小；只保留下一步的子树 |
| 每步都从零开始 | 没有复用上一步的树 | 走完一步后，把对应的子树作为新的根 |
| 掉进几步之内的陷阱 | 随机模拟恰好没覆盖到对方的强制路线 | 模拟中检查立即获胜；在 MCTS 的叶子上做浅层的 Minimax（MCTS-Minimax 混合） |

## 练习

1. **树的复用**：AI 走完一步、对手回应之后，把这两步对应的子树作为新的根继续搜索，而不是从零开始。同样的迭代次数下，棋力提高了多少？
2. **MCTS-Solver**：一个节点的所有子节点都是对方的终局胜利时，这个节点就是确定的失败，可以直接标记并向上传递，不必再模拟。实现它，并在浅层陷阱的测试上比较。
3. **RAVE / AMAF**：模拟中走过的着法，即使不在当前路径上，也"顺便"更新兄弟节点的统计。在每步着法很多的游戏中，这能大大加快早期的收敛。
4. **按时间搜索**：把"迭代次数"换成"每步 x 毫秒"，与上一篇的迭代加深 Alpha-Beta 在相同的时间下对局。
5. **非完全信息**：设计一个简单的卡牌游戏（比如双方各有 5 张隐藏的牌，轮流出牌比大小），用确定化的 MCTS 实现 AI，并与"看得到对方手牌"的 AI 比较。
