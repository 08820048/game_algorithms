在地图上放一些城镇，每一块土地归离它最近的城镇所有，这样划出来的领地就是 **Voronoi 图**：每个点（称为"站点"）拥有一个凸多边形的**单元**，单元里的任何位置离这个站点都比离其他站点近。游戏里它到处出现：势力范围、生物群系的分区、"最近的商店"、碎裂效果，以及第 4.2 节的 Worley 噪声（它就是 Voronoi 单元的距离场）。

把单元相邻的两个站点连起来，得到的就是 **Delaunay 三角剖分**。两者是同一个结构的两面（**对偶**）：每条 Delaunay 边对应一条 Voronoi 边，并且被它垂直平分；每个 Delaunay 三角形对应一个 Voronoi 顶点，就是这个三角形的外心。Delaunay 三角剖分在游戏里也很常用：把地牢的房间连成图再取最小生成树（第 4.4 节的"房间与走廊"的另一种做法）、导航网格、地形的不规则三角网。

Delaunay 三角剖分有一条决定性的性质：

> **空外接圆**：每个三角形的外接圆里都没有别的点。

满足这条性质的三角剖分在所有三角剖分中**最小角最大**，也就是尽量避免细长的三角形。点不全共线、且没有四点共圆时，它是唯一的。

## 两个判断

整个算法只依赖两个几何判断（称为**谓词**）：

- **orient(a, b, c)**：c 在有向线段 a→b 的左侧、右侧还是线上。就是叉积 (b − a) × (c − a) 的符号。
- **inCircle(a, b, c, d)**：d 在三角形 abc 的外接圆内、圆上还是圆外。是一个 3×3 行列式的符号。

这里给了三种精度：float、double，以及精确版。精确版要求坐标是整数（|x| < 2²⁴），用 128 位整数计算，不会有舍入。后面会看到这三者的差别。

## Bowyer–Watson 算法

逐个插入点。每插入一个点 q：

1. 找出所有外接圆包含 q 的三角形。它们连成一片，称为**空腔**（cavity）。
2. 删掉空腔里的三角形。
3. 空腔边界的每条边和 q 连成一个新三角形。

空腔一定是一个以 q 为"中心"的星形区域，所以新三角形不会重叠。新三角形都满足空外接圆，因为外接圆受影响的三角形都已经被删掉重建了。

一开始只有一个三角形，后面的点落在它外面怎么办？经典的做法是先放一个很大的**超级三角形**把所有点包住，最后删掉碰到它的三角形，后面会测量这种做法的问题。这里用另一种做法：加一个**无穷远点**，凸包的每条边和它组成一个"幽灵三角形"，代表凸包边外侧的那片半平面。点落在凸包外时，"外接圆包含 q"对幽灵三角形的含义是 q 在这条凸包边的外侧，所以算法不需要任何特殊处理。

<CppSnippet file="procgen/voronoi/delaunay.h" region="cavity" />

空腔从一个冲突的三角形出发向外扩展；冲突与不冲突的交界就是边界。新三角形 (a, b, q) 之间的邻接关系靠边界顶点配对：空腔是一个圆盘时，每个边界顶点恰好是一条边界边的起点、另一条的终点。如果不是（只有在谓词前后矛盾时才会发生），三角网就已经损坏，函数停止插入并报告。

## 找到新点落在哪个三角形里

第 1 步需要先找到一个包含 q 的三角形。最简单的方法是**走过去**：从上一次新建的三角形出发，只要 q 在当前三角形某条边的外侧，就跨过这条边，直到 q 在三角形内（或走进幽灵三角形，说明 q 在凸包外）。

<CppSnippet file="procgen/voronoi/delaunay.h" region="locate" />

走多远取决于插入顺序。随机顺序下，相邻两次插入的点在空间上毫无关系，平均要穿过 O(√n) 个三角形，总耗时变成 O(n^1.5)。解决办法是先按**希尔伯特曲线**给点排序：这条曲线连续地填满正方形，曲线上相邻的点在平面上也相邻。

<CppSnippet file="procgen/voronoi/delaunay.h" region="order" />

正方形里的均匀随机点，double 谓词，每个点的平均值：

| n | 插入顺序 | 走过的三角形 | 冲突测试 | 删掉的三角形 | 用时 |
|---|---|---|---|---|---|
| 1,000 | 随机 | 26.4 | 9.7 | 3.85 | 1.6 ms |
| | 按 x 排序 | 14.0 | 16.6 | 7.33 | 1.7 ms |
| | 希尔伯特 | 2.5 | 11.2 | 4.63 | 1.3 ms |
| 100,000 | 随机 | 254.7 | 10.0 | 4.00 | 814 ms |
| | 按 x 排序 | 166.6 | 27.7 | 12.89 | 300 ms |
| | 希尔伯特 | 2.8 | 13.1 | 5.59 | 62 ms |
| 1,000,000 | 按 x 排序 | 540.6 | 33.2 | 15.66 | 13.9 s |
| | 希尔伯特 | 2.9 | 13.5 | 5.79 | 834 ms |

（测量时机器负载约 15，用时只能当量级参考；步数和三角形数不受影响。）

- **随机顺序的走路步数按 √n 增长**：n 每乘 10，步数乘约 3.1。10 万个点时走路占了绝大部分时间，比希尔伯特顺序慢 13 倍。
- **希尔伯特顺序的步数几乎不随 n 变化**：始终在 3 步以内。100 万个点用时 0.8 秒。
- **按 x 排序反而是两头吃亏**：每个新点都在已有三角网的右边，也就是在凸包外，空腔里有一长串幽灵三角形，而且随 n 变大（100 万个点时平均删掉 15.7 个）；上一个新三角形又不一定靠近下一个点，走路也长。
- **随机顺序删掉的三角形平均恰好是 4**：这是理论上的期望值。倒过来想：随机顺序下，最后插入的点是 n 个点中的任意一个，它在最终三角网里的平均度数是 6（欧拉公式），所以插入它时新建 6 个三角形、删掉 4 个。希尔伯特顺序删掉 5.6 个，多出来的是因为新点总是落在"已插入区域"的边缘，那里的三角形又长又大，之后才会被附近的点切碎。它多做约 30% 的冲突测试，换来的是走路几乎为零，总体上快得多。

## 超级三角形漏了什么

经典写法：先放三个离点集很远的真实顶点，组成一个包住所有点的三角形，插完所有点后删掉碰到这三个顶点的三角形。问题是这三个顶点不在无穷远。凸包附近的某些三角形，外接圆非常大，会把超级顶点也包进去，于是这些三角形不会出现在结果里，换成了连到超级顶点的三角形，最后被一起删掉。

2000 个随机整数点，坐标在 [0, 1000) 内，每组 10 个种子，正确答案平均 3,974 个三角形：

| 超级顶点的距离（包围盒的倍数） | 结果的三角形数 | 缺少的 | 错误的 | 缺少的凸包边 |
|---|---|---|---|---|
| 1 | 3,953.5 | 21.0 | 0 | 7.0 |
| 2 | 3,958.5 | 16.0 | 0 | 6.1 |
| 10 | 3,969.0 | 5.5 | 0 | 3.5 |
| 100 | 3,973.9 | 0.6 | 0 | 0.6 |
| 1,000 | 3,974.5 | 0 | 0 | 0 |

- **只会缺，不会错**：留下的三角形外接圆里连超级顶点都没有，更没有真实的点，所以一定是真的 Delaunay 三角形。测试也验证了这一点。缺的都在凸包附近，结果的外边界会凹进去一块，"凸包边缺失"就是这个意思。
- **距离取到 1000 倍包围盒才不缺**。缺的三角形需要的距离取决于凸包附近最"扁"的那几个三角形，没有一个对所有输入都安全的倍数。
- 我原本担心距离太远会让 double 的判断失准。实际测到 10⁷ 倍包围盒（坐标约 10¹⁰），结果和精确版完全一样。可能的原因是：牵涉超级顶点的判断，结论都非常明确，离临界情况很远。

无穷远点的写法没有这个问题，也不需要选一个倍数，代价只是冲突测试里多一个分支。

## 精度

两个谓词都是"算一个值，看它的符号"。值接近 0 时，舍入误差可能让符号算错。Bowyer–Watson 对此很敏感：同一个点对相邻三角形的判断如果互相矛盾，空腔就可能不是一个圆盘，三角网会损坏。

最难的输入是**几乎共圆**的点。下表的点取在半径为 R 的圆上，坐标四舍五入到整数（再平移到 2²³ 附近，保证 float 能精确表示）；"违反空外接圆"用精确谓词检查：

| R | 精度 | 结果 | 违反空外接圆的次数 |
|---|---|---|---|
| 2¹⁰ | float | 合法 | 0 |
| 2¹⁴ | float | 合法 | 0 |
| 2¹⁸ | float | 结构合法 | 3,310 |
| 2²² | float | 结构合法 | 42,936 |
| 2¹⁰ ~ 2²² | double、精确 | 合法 | 0 |

如果再加上圆心，float 在 R = 2¹⁸ 时插到第 1,422 个点就出现了不是圆盘的空腔，三角网损坏。

单独看 inCircle 本身：随机取三个整数点，第四个点取离它们外接圆**最近的整数点**，各 100 万组：

| 坐标范围 | 恰好共圆 | float 算错符号 | double 算错符号 |
|---|---|---|---|
| [0, 2⁸) | 0.91% | 0.011% | 0 |
| [0, 2¹²) | 0.057% | 0.005% | 0 |
| [0, 2¹⁶) | 0.003% | 0.16% | 0 |
| [0, 2²⁰) | 0 | 2.3% | 0 |
| [0, 2²³) | 0 | 11.4% | 0 |

- **float 不能用来做判断**：坐标到 800 万（2²³）时，十组几乎共圆的输入就有一组算错。
- **double 在这些测试里一次都没错**。粗略地解释：整数点离圆周最近也有零点几个单位，对应的行列式值比 double 的舍入误差大很多个数量级。这不是证明，专门构造的输入（例如几乎共线的点配上很远的点）仍然可能让 double 出错；需要绝对可靠时，用 Shewchuk 的自适应精确谓词，或者像这里一样把坐标量化成整数后精确计算。
- **精确计算并不贵**：100 万个整数点，128 位整数版 981 ms，double 版 925 ms，只慢 6%。大部分时间花在内存访问上，不在算术上。

<Aside type="caution" title="FMA 的陷阱">
第一版 float 谓词在第 3 个点就让三角网损坏了，原因不是精度，而是编译器。按定义 orient(a, b, b) 应该恰好是 0：两个乘积 (b.x − a.x)(b.y − a.y) 完全相同，相减为 0。但在 ARM 上，编译器默认会把"乘再减"合并成一条 FMA 指令，其中一个乘积不经舍入就参与减法，结果是舍入误差本身，不是 0。建第一个三角形时，算法因此把 a、b、b 当成了不共线的三个点。修正是显式排除同一个点；更一般的教训是：浮点谓词的结果甚至和编译选项有关（`-ffp-contract=off` 时 float 的错误率又不一样）。double 版不受影响，因为 float 坐标之差的乘积在 double 里是精确的。
</Aside>

## Voronoi 单元

有了 Delaunay 三角剖分，Voronoi 单元很容易求。站点 i 的单元是若干半平面的交：对每个其他站点 j，保留 i、j 的垂直平分线靠 i 的一侧。只需要对 **Delaunay 邻居**做这件事，别的站点的平分线不会切到单元。从边界框出发，每个邻居切一刀：

## Lloyd 松弛

把每个站点移到自己单元的**质心**，重新计算 Voronoi 图，再移动……这就是 **Lloyd 松弛**。每一步都让总能量 Σ∫|x − 站点|²（单元里每个位置到站点的距离平方之和）不增加，最终收敛到**重心 Voronoi 图**（centroidal Voronoi tessellation）：每个站点恰好在自己单元的质心上。平面上能量最低的排列是正六边形蜂窝。

### 邻居数

60×60 的区域，约 3000 个点，只统计不碰边框的内部单元：

| 点集 | 五边形 | 六边形 | 七边形 | 其他 | 平均邻居数 | 单元面积的变异系数 | 最近邻距离 / 平均间距 |
|---|---|---|---|---|---|---|---|
| 白噪声 | 26.6% | 29.3% | 19.5% | 24.6% | 5.96 | 0.53 | 0.02 |
| 抖动网格 | 26.5% | 38.1% | 22.0% | 13.4% | 5.98 | 0.25 | 0.04 |
| Bridson（k = 30） | 25.4% | 47.9% | 21.7% | 5.0% | 5.99 | 0.15 | 0.79 |
| 白噪声 + Lloyd 1 次 | 28.2% | 36.8% | 21.2% | 13.8% | 5.98 | 0.38 | 0.19 |
| 白噪声 + Lloyd 5 次 | 25.4% | 48.6% | 21.4% | 4.7% | 5.99 | 0.23 | 0.46 |
| 白噪声 + Lloyd 30 次 | 17.5% | 65.6% | 16.6% | 0.3% | 6.00 | 0.12 | 0.73 |
| 白噪声 + Lloyd 300 次 | 7.7% | 84.6% | 7.7% | 0 | 6.00 | 0.06 | 0.83 |

- **平均邻居数总是 6**，不管点怎么分布。这是欧拉公式的结论：平面三角剖分里，内部顶点的平均度数趋于 6。点的分布只改变邻居数的**方差**。
- **Bridson 的邻居数分布相当于白噪声做 5 次 Lloyd**，但最近邻距离好得多（0.79 对 0.46）。Lloyd 先消除大的不均匀，最小距离要很多次迭代才拉开。
- **300 次之后五边形和七边形各占 7.7%，数量恰好相等**。它们成对出现，是六边形晶格里的位错；位错要移动很远才能消失，所以消除得非常慢。

### 收敛有多慢

2000 个点，50×40 的区域，每组 5 个种子；能量以同样点数的完美六边形为 1：

| 迭代次数 | 能量（白噪声起点） | 平均移动 / 平均间距 | 能量（Bridson 起点） |
|---|---|---|---|
| 0 | 2.014 | 0.23 | 1.143 |
| 1 | 1.346 | 0.098 | 1.080 |
| 5 | 1.114 | 0.030 | 1.048 |
| 10 | 1.070 | 0.017 | 1.037 |
| 50 | 1.028 | 0.0037 | 1.022 |
| 100 | 1.021 | 0.0021 | 1.018 |
| 1,000 | 1.011 | 0.00017 | 1.012 |

- **前几次迭代收益最大**：第 1 次就去掉了白噪声多余能量的 2/3。
- **之后移动量大约按 1/迭代次数衰减**，能量离 1 的差距下降得更慢：100 次后还差 2.1%，1000 次后还差 1.1%。剩下的差距来自边界（矩形放不下完美的蜂窝）和位错。
- **Bridson 起点的优势只维持几十次迭代**：50 次后两者已经差不多，1000 次时几乎一样。
- 游戏里通常只做 **1~3 次**：点已经足够均匀，又不会规整到看出是人工排列的。

一次迭代（2000 个点，三角剖分加上求所有单元）用时 2.8 ms。

## 测试

- **小点集和逐个三元组的暴力枚举对照**：600 组 3~14 个随机整数点，四种插入顺序 × 两种精度，在没有四点共圆的情况下得到完全相同的三角形集合（比较了 2000 多次）。
- **退化输入**：整数网格（到处是四点共圆，凸包边上全是共线点）、全部共线、点落在凸包边上和凸包边的延长线上、每个点重复一次。检查三角形数 = 2n − 2 − h（h 是凸包上的点数，包括共线的点）、凸包大小、空外接圆。
- **大点集**：3000 个点，用精确谓词逐个检查每个三角形的外接圆；邻接关系对称；包括幽灵三角形在内的总数恰好是 2n − 2。
- **空腔**：每次插入记下被删掉的三角形，它们恰好是外接圆包含新点的那些。
- **Voronoi、质心、二阶矩**：和"对所有站点裁剪"、细网格上的数值积分对照。
- **Lloyd**：能量单调不增；返回的能量和细网格上"每个采样点到最近站点的距离平方"的积分一致；收敛后接近六边形下界。
- **希尔伯特编号**：16×16 的格子一一对应，相邻编号的格子相邻。

变异测试：故意改坏 22 处，第一轮发现 16 处。没发现的 6 处里有 4 处是等价变异：

- "外接圆严格包含"改成"包含或在圆上"：四点共圆时两种写法都给出合法的 Delaunay 三角剖分，只是空腔大小不同。
- 共线点的判断改成闭区间：只有新点与已有顶点重合时有区别，而重合的点在这之前已经被跳过。
- 走路时不轮换起始边：在精确谓词下，Delaunay 三角网上的走路已知一定会终止。
- 超级三角形的过滤少查一个顶点：因为超级顶点最先插入，之后新三角形的第三个顶点总是刚插入的点，所以超级顶点不会出现在那个位置。这是巧合，代码里仍然检查三个顶点。

真正漏掉的两处是：**float 谓词偷偷用 double 计算**（float 的路径没有测试覆盖），以及 **Lloyd 返回移动之后的能量**（单调性依然成立）。补上"float 在大坐标的近共圆输入上会算错、double 不会"和"能量与数值积分对照"两项测试后，22 处中 18 处被发现，其余 4 处是上面的等价变异。

## 常见陷阱

| 问题 | 原因 | 解决 |
|---|---|---|
| 凸包附近缺三角形 | 超级三角形不够大 | 用无穷远点；或者超级顶点放到包围盒的 1000 倍以外，并检查结果 |
| 三角网偶尔损坏、程序崩溃 | 谓词用 float 计算，判断前后矛盾 | 至少用 double；需要绝对可靠时用精确谓词 |
| 共线、共圆的输入出错 | 把 = 0 的情况当成了 > 0 或 < 0 | 用整数网格测试；凸包边上的共线点要单独处理 |
| 大点集非常慢 | 随机顺序插入，走路 O(√n) | 按希尔伯特曲线排序 |
| 按坐标排序后反而更慢 | 每个点都在凸包外，空腔很大 | 用希尔伯特曲线，不要按单一坐标排序 |
| 边界上的 Voronoi 单元是无界的 | 凸包上的站点的单元延伸到无穷远 | 用边界框裁剪 |
| Lloyd 迭代很多次还在动 | 收敛慢，位错难以消除 | 只做 1~3 次；需要规整时直接用六角网格加扰动 |
| 判断 orient(a, b, b) 不是 0 | 编译器合并成 FMA | 显式处理相同的点；谓词用 double |

## 练习

1. **地牢连通**：把第 4.4 节的房间中心做 Delaunay 三角剖分，取最小生成树作为走廊，再随机加回 15% 的边形成环路。和"每个房间连最近的房间"相比，连通性和走廊长度如何？
2. **多边形地图**：在泊松圆盘点上做 Voronoi 图，用第 4.1 节的噪声决定每个单元是陆地还是海洋，再沿 Delaunay 边从海岸向内计算距离作为海拔。
3. **周期边界**：把点复制到上下左右八个邻居格子里再三角剖分，只保留中间的部分，得到可以无缝拼接的 Voronoi 图。
4. **删除点**：实现从 Delaunay 三角剖分中删除一个点（把它的邻居多边形重新三角剖分）。用逐个三元组的暴力枚举检查结果。
5. **加权 Voronoi**：给每个站点一个权重，单元按"距离² − 权重"划分（power diagram）。平分线怎么变？Lloyd 松弛还成立吗？
