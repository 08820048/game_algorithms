## 卷四导读：程序化生成

前几卷处理的都是"已经存在的世界"：在地图上找路、让物体碰撞、让角色做决定。这一卷回答另一个问题：**地图本身从哪里来**。

程序化生成用算法代替手工制作内容：地形、洞穴、地牢、植物、城市。它的价值不只是省人力。一个种子就能复现整个世界，所以存档只需要存种子；世界可以无限大，走到哪里生成到哪里；每局都不同，重玩价值更高。代价是可控性：算法生成的东西容易"随机但无聊"，所以这一卷的每种方法都会讨论怎样控制它。

| 章节 | 方法 | 生成什么 |
|---|---|---|
| 4.1 ~ 4.3 | 噪声、分形叠加、地形 | 连续变化的量：高度、湿度、温度、纹理 |
| 4.4 ~ 4.5 | BSP、随机游走、元胞自动机 | 离散的空间结构：房间、走廊、洞穴 |
| 4.6 ~ 4.7 | 泊松圆盘采样、Voronoi | 散布的点与区域划分：树木、城市、国界 |
| 4.8 ~ 4.9 | 波函数坍缩、L-System | 满足规则的图案与递归结构：瓦片地图、植物 |

这一篇从最基础的工具开始：噪声。

## 为什么不直接用随机数

想生成一片起伏的地形，最直接的想法是给每个点一个随机高度。结果是**白噪声**：相邻两点毫无关系，看起来像电视雪花，不像任何自然的东西。

自然界的起伏是**连续**的：山坡上相邻两点的高度差不多，远处的两点才可能差很多。我们需要的是这样一个函数 `noise(x, y)`：

- **平滑**：相邻的点值相近，没有跳变；
- **随机**：整体看不出规律，不同位置的起伏各不相同；
- **确定**：同一个种子、同一个坐标，永远得到同一个值；
- **随机访问**：可以直接求任意位置的值，不需要先算它周围，也不需要存储——这样世界才能无限大、按需生成；
- **尺度可控**：起伏的大小大致固定（比如"每隔一个单位起伏一次"），通过缩放坐标就能得到大山或小丘。

Ken Perlin 参与了电影《电子世界争霸战》（1982）的特效制作，不满意当时电脑图像过于光滑、"像机器做的"样子，于 1983 年设计了第一种满足这些条件的噪声，后来因此获得了奥斯卡技术成就奖。它和更简单的 Value Noise 有共同的结构，叫做**格点噪声**（lattice noise）：

1. 在每个整数格点 (i, j) 上放一个随机量；
2. 对任意一点 p，找到它所在格子的四个角，用插值把四个角的量混合起来。

两者的区别只在第一步放的是什么。

## 格点上的随机量：哈希

第一步要求"每个格点一个随机量"，但格点有无穷多个，不可能预先存好。办法是用**哈希函数**：把格点坐标 (i, j) 和种子混合成一个看起来随机的整数。同一个输入永远得到同一个输出，这就满足了"确定"和"随机访问"。

<CppSnippet file="procgen/noise/noise.h" region="lattice" />

这里有两种做法：

- **置换表**（`PermLattice`）：Perlin 原版的做法。把 0~255 随机打乱成一张表 `p`，格点 (i, j) 的哈希是 `p[p[i] + j]`。只查两次表，非常快；但坐标只取低 8 位，所以**噪声每隔 256 个单位就完全重复一次**。测试里验证了 `noise(x + 256, y) == noise(x, y)` 精确成立。
- **整数哈希**（`HashLattice`）：用 MurmurHash3 的混合函数 `mix32` 代替查表，结构与置换表相同（先混合 x，再加上 y 混合一次），但没有 256 的周期。代价是更慢，后面有实测。

无论哪种，哈希都要"足够乱"。测试检查了 9 万个格点：8 个梯度编号的分布通过卡方检验，相邻格点（横向、对角、反对角）的值的相关系数都小于 0.02。这些检查并不多余：把置换表改成只查一次 `p[(i + j) & 255]`，噪声沿反对角线就变成了常数，这正是反对角相关性检查抓到的。

`HashLattice` 还支持 `period`：坐标先取模，噪声就以 period 为周期无缝平铺，适合生成可以重复贴的纹理。取模时要注意负数：C++ 的 `%` 对负数返回负值，必须修正回 [0, period)。

## Value Noise

最简单的格点噪声：每个格点上放一个 [-1, 1] 之间的随机**值**，格子内部用双线性插值——先沿 x 方向插两次，再沿 y 方向插一次。

<CppSnippet file="procgen/noise/noise.h" region="value" />

插值的权重 u、v 不直接用格子内的位置 t，而是先经过一个**缓和函数** `fade(t)`：

<CppSnippet file="procgen/noise/noise.h" region="fade" />

为什么需要它？直接用 t（linear）时，每个格子里的曲面都由直线拼成，跨过格线时**斜率会突变**，形成折角。smoothstep `3t² − 2t³` 在两端的斜率为 0，于是拼接处斜率连续；但它的二阶导数在两端是 ±6，所以**曲率仍然会突变**。Perlin 在 2002 年的改进版里换成了 quintic `6t⁵ − 15t⁴ + 10t³`，两端的一阶、二阶导数都是 0。

用下面的演示看这三者的区别。上面一行是噪声本身，下面两行是它的一阶导数 f′ 和二阶导数 f″，格点处的跳变用朱红色竖线标出：

<Demo name="noise_1d" title="一维格点噪声" label="图 4.1a" caption="value 模式：格点上的圆点是随机值，可以上下拖动。gradient 模式：格点上的短线是随机斜率，噪声在每个格点上都是 0，拖动短线末端改变斜率。上方切换缓和函数：linear 时 f′ 在每个格点都跳变（f 有折角）；smooth 时 f′ 连续、f″ 跳变；quintic 时 f″ 也连续。parts 打开时，鼠标所在的格子里会用虚线画出两端各自的贡献，噪声就是在它们之间插值。flat 把所有格点清零，只留下中间一个，方便观察单个格点影响的范围。" />

实测跨过格线时导数的跳变（沿 2,000 条格线取样）：

| 缓和函数 | Value：f′ 跳变（最大 / 平均） | Value：f″ 跳变 | Perlin：f′ 跳变 | Perlin：f″ 跳变 |
|---|---|---|---|---|
| linear | 3.49 / 0.92 | 0 | 2.80 / 0.75 | 7.30 / 2.30 |
| smoothstep | 0 | 11.37 / 3.54 | 0 | 12.36 / 4.32 |
| quintic | 0 | 0.02 / 0.01（数值误差） | 0 | 0.02 / 0.01（数值误差） |

（linear 的 Value Noise 在格子内是分段直线，两侧的 f″ 都是 0，所以 f″ 一栏没有跳变；它的问题在 f′。）

## Perlin Noise

Value Noise 有一个看起来无害的性质：用 smoothstep 或 quintic 时，**每个格点处的梯度都正好是 0**（因为缓和函数两端的斜率为 0）。每个格点都是一个平点：山顶、谷底或鞍点。后面会看到，这让网格的痕迹很明显。

Perlin 的做法是在格点上放随机的**梯度**（一个方向向量 g），而不是值。每个角对采样点 p 的贡献是 `g · (p − 角)`：一个经过该角、沿 g 方向倾斜的平面。四个角的平面再用同样的缓和函数插值：

<CppSnippet file="procgen/noise/noise.h" region="perlin" />

这带来两个性质：

- **格点上的值总是 0**：p 落在角上时，`p − 角` 是零向量。测试中对 3 种缓和函数、41×41 个格点逐一检查，结果都精确等于 0。
- **格点上的梯度正好是 g**（smoothstep 与 quintic）。起伏的"拐点"由随机方向决定，而不是固定在格点上。

在图 4.1a 中切换到 gradient 模式就能看到一维的情形：噪声在每个格点穿过 0，斜率由短线决定；打开 parts，两条虚线就是左右两端的直线，噪声在它们之间平滑过渡。

梯度的选择会影响结果。这里用 8 个单位向量（4 个轴向、4 个对角），用哈希的低 3 位选择。Perlin 2002 年的三维版本用的是 12 个指向立方体棱中点的向量，不需要归一化，查表更快。

### 解析导数

很多地方需要噪声的梯度：地形的法线和光照、坡度、沿坡度方向的侵蚀、用噪声扰动流场……用有限差分求要多算 2~4 次噪声，而且有误差。把插值展开成 `k0 + k1·u + k2·v + k3·u·v`，就能直接求导：

<CppSnippet file="procgen/noise/noise.h" region="derivatives" />

Perlin 的导数分两部分：每个角的贡献 `g · (p − 角)` 对 p 的导数就是 g，所以第一部分是"被插值的梯度"；第二部分来自权重 u、v 随位置的变化。测试中与中心差分比较 5,000 个随机点，误差小于 10⁻⁶。

- **value + linear + shade**：每个格子都是一块拼接的曲面，格线处有明显的折痕。
- **value + quintic + bands + lattice**：等值线围着格点打转，很多"山头"正好落在格点上。

## 实测：两种噪声有什么不同

以下统计都用 quintic 缓和函数、`HashLattice`，在随机位置大量采样。

### 取值范围与分布

| 噪声 | 标准差 | 1% 分位 | 99% 分位 | 观察到的最大绝对值 | 绝对值 > 0.5 的比例 |
|---|---|---|---|---|---|
| Value | 0.4525 | −0.895 | 0.895 | 1.0000 | 31.8% |
| Perlin | 0.2156 | −0.466 | 0.466 | 0.7061 | 0.77% |

一个常见的误解是"Perlin 噪声的范围是 [−1, 1]"。用单位梯度时，二维 Perlin 噪声的理论上限是 **√2/2 ≈ 0.7071**，在格子中心、四个角的梯度都指向中心时取到。测试对四个角梯度的全部 8⁴ = 4096 种组合逐一检查，最大值正好是 √2/2；400 万次随机采样观察到的最大值是 0.7061。

而实际的值远小于上限：**99% 落在 ±0.466 以内，超过 0.5 的只有 0.77%**。如果把 Perlin 噪声直接当作 [−1, 1] 的值来用（比如映射到 0~255 的灰度，或者用阈值 0.6 判断"山峰"），结果会显得很平、几乎碰不到阈值。图 4.1b 的灰度模式故意没有拉伸，就是为了看到这一点。实践中应当按实测的分布来缩放和设阈值，而不是按理论范围。

分布的形状也不同。分布关于 0 对称，下表只列出右半边，每个宽 0.1 的区间所占的比例：

| 区间 | Value | Perlin |
|---|---|---|
| 0.0 ~ 0.1 | 7.5% | 16.5% |
| 0.1 ~ 0.2 | 7.3% | 15.3% |
| 0.2 ~ 0.3 | 6.9% | 9.3% |
| 0.3 ~ 0.4 | 6.5% | 5.8% |
| 0.4 ~ 0.5 | 5.9% | 2.8% |
| 0.5 ~ 0.6 | 5.1% | 0.4% |
| 0.6 ~ 0.7 | 4.3% | 0.0% |
| 0.7 ~ 0.8 | 3.3% | 0.0% |

Value Noise 宽而平，Perlin 窄而尖。

### 格点的痕迹

为什么能"看出网格"？因为两种噪声的统计性质都随**在格子里的位置**变化。在 100 万个格子的同一相对位置取样：

| 格子内的位置 | Value：标准差 | Perlin：标准差 | Value：平均梯度大小 | Perlin：平均梯度大小 |
|---|---|---|---|---|
| 角 (0, 0) | 0.577 | **0** | **0** | 1.000 |
| 边中点 (0.5, 0) | 0.408 | 0.250 | 1.251 | 0.590 |
| 中心 (0.5, 0.5) | 0.289 | 0.250 | 1.382 | 0.933 |

- **Value Noise**：格点上是原始的随机值，标准差是 [−1, 1] 均匀分布的 1/√3 ≈ 0.577；到格子中心是四个值的平均，标准差减半到 0.289。同时格点上的梯度恒为 0。于是格点处"起伏大且平坦"，格子中心"起伏小且陡"——这个规律每个格子都一样，眼睛很容易发现。
- **Perlin**：格点上恒为 0，梯度大小恒为 1；边中点和中心的标准差几乎相同（0.250 与 0.250）。格点的痕迹弱得多，但没有消失：所有格点都在 0 这条等值线上。

另一种常见的担心是"方向性"：网格对齐的噪声会不会沿坐标轴和对角线表现不同？先看相距 r 的两点的相关系数：沿轴向与沿对角的差别最大只有 0.039（Perlin，r = 1：−0.135 与 −0.174），Value Noise 最大 0.020。从这个指标看，方向性很小。

但光照用的是梯度，所以更该看**梯度的方向**是否偏向某些角度。统计 E[cos 4θ]（θ 是梯度方向，按梯度大小加权）：各向同性时为 0，梯度全部沿坐标轴时为 +1，全部沿对角线时为 −1：

| 缓和函数 | Value | Perlin |
|---|---|---|
| linear | +0.048 | +0.142 |
| smoothstep | +0.295 | −0.040 |
| quintic | **+0.444** | −0.074 |

这个结果出乎我的预料：**Value Noise 的梯度强烈偏向坐标轴，而且缓和函数越平滑，偏得越厉害**。原因在导数公式里：x 方向的导数带有因子 `fadeD(tx)`，靠近竖直格线时它趋于 0，梯度只剩 y 分量；靠近水平格线时只剩 x 分量。smoothstep 和 quintic 正是为了让格线处导数为 0 而设计的，这一"优点"在二维里变成了方向偏差。在图 4.1b 中用 value + quintic + shade 就能看到：沿每条格线都有一条横向或纵向的带子，坡面在那里只朝一个方向倾斜，整体有明显的"方块感"。Perlin 的导数里还有"被插值的梯度"这一项，它不会在格线处消失，所以几乎各向同性。

### 频谱

另一个角度是看噪声包含哪些频率的起伏。对 256×256 的采样块做二维 FFT，按频率的大小 \|f\|（每个格子单位内的周期数）分段统计功率：

| 噪声 | 0~0.125 | 0.125~0.25 | 0.25~0.5 | 0.5~0.75 | 0.75~1 | 1~1.5 | 峰值 |
|---|---|---|---|---|---|---|---|
| Value，linear | 9.7% | 24.8% | 49.8% | 14.3% | 0.9% | 0.3% | 0.03 |
| Value，quintic | 7.1% | 20.1% | 46.7% | 22.1% | 3.5% | 0.5% | 0.03~0.13（平坦） |
| Perlin，linear | 0.4% | 5.3% | 42.5% | 42.0% | 8.4% | 0.7% | 0.41 |
| Perlin，quintic | 0.2% | 2.9% | 27.3% | 43.3% | 22.6% | 3.5% | 0.50 |

按功率谱密度看（相对峰值），quintic 的 Value Noise 在频率为 0 处仍有峰值的 79%，而 Perlin 只有 1%：

- **Value Noise 的能量一直延伸到最低频**。格点值是独立随机的，几个相邻格点碰巧都偏高的情况并不少见，形成跨越多个格子的大块区域。所以 Value Noise 的"起伏尺度"不太确定。
- **Perlin Noise 是带通的**：几乎没有低频，能量集中在每格 0.5 个周期附近（也就是每两个格子起伏一次）。这是因为每个格点的贡献 `g · (p − 角)` 一边为正、一边为负，平均为 0，不会累积出大块的偏移。

带通意味着 Perlin 噪声的"起伏尺度"更确定：每两个格子起伏一次，很少出现跨越很多格子的大块区域。

<Aside type="caution" title="更正">
本文最初在这里写道："Value Noise 混有大量低频，叠加成分形布朗运动时各层会互相干扰，很难控制最终的频谱，这是 Perlin 取代 Value Noise 的主要原因。"[4.2](/procgen/fractal/) 实测推翻了这个说法：用 Value Noise 叠加，频谱斜率与理论值的偏差只比 Perlin 稍大（0.08~0.15 对 0.02~0.03），频谱反而更平滑。Value Noise 真正的问题是本节后面的格点痕迹和梯度的方向偏差。
</Aside>

<Aside type="caution" title="不要用一条直线做频谱">
我第一次测量时只沿水平直线采样、做一维 FFT，得到的结果是 Perlin 也有 16% 的功率在 0.125 以下。这是错的：沿直线切片得到的是二维谱在一个方向上的投影，所有 f_x 很小、f_y 很大的成分都被算成了低频。二维噪声要用二维 FFT 按 |f| 统计。
</Aside>

| Value，整数哈希，同时求梯度 | 5.5 ns |
| Perlin，整数哈希，double | 6.4 ns |

- **整数哈希比置换表慢约 3 倍**。置换表只有 512 字节，常驻 L1 缓存，查两次表就够了；整数哈希每个角要做两到三次 `mix32`，每次两个乘法。换来的是没有 256 的周期。如果世界不超过 256 个格子，或者重复不容易被注意到，置换表是更好的选择。注意下一章叠加多层噪声时，如果每层的频率都是上一层的 2 倍，各层的周期都整除 256，叠加后仍然每 256 个单位重复一次。
- **求梯度几乎是免费的**：解析导数复用了插值的中间量，只多了约 1 ns。
- float 与 double 差别不大。

一张 1024×1024 的高度图只需要几毫秒。

### 离原点很远时：float 的台阶

开放世界游戏里，坐标可能达到几十万甚至上百万。float 只有 24 位有效数字，坐标越大，小数部分越粗。在不同的偏移处，每个格子横向采样 256 个点，与 double 的结果比较：

| 坐标大小 | float 的最小间距 | 每个格子里不同的采样位置 | 平均误差 | 最大误差 |
|---|---|---|---|---|
| 1,000 | 6.1×10⁻⁵ | 256 | < 10⁻⁵ | < 10⁻⁴ |
| 10,000 | 0.001 | 256 | < 10⁻⁵ | < 10⁻⁴ |
| 100,000 | 0.0078 | 129 | 0.001 | 0.007 |
| 1,000,000 | 0.0625 | **17** | 0.008 | 0.048 |
| 4,000,000 | 0.25 | **5** | 0.033 | 0.226 |
| 16,000,000 | 1 | **2** | 0.120 | 0.602 |

坐标到 100 万时，每个格子里只剩 17 个不同的位置，噪声变成了台阶；到 1600 万，float 只能表示整数，x 方向的变化完全消失，最大误差达到 0.6，接近 Perlin 噪声的整个范围。

解决办法：坐标较大时改用 double；或者把世界分成区块，区块编号用整数、区块内的偏移用 float，求噪声时先分别算出格点编号和格内位置，避免先把它们相加成一个大 float。

<Aside type="note" title="测试环境">
Apple M3，Apple clang 21，`-O2`。测量时机器上有其他负载（平均负载 4~13），用时有明显波动：负载高时整数哈希版本测到过 8~10 ns，置换表版本 2.6~3.0 ns，比例基本不变。分布、频谱和精度统计是确定性的，与负载无关。代码在 `cpp/procgen/noise/noise_bench.cpp`。
</Aside>

## 测试

- **与暴力写法逐点一致**：噪声可以换一种写法——不分格子、不嵌套插值，而是对周围所有格点求和，每个格点的贡献乘以 `K(x − i) · K(y − j)`，其中 `K(t) = 1 − fade(|t|)`。两种写法相等的前提是缓和函数关于 (½, ½) 对称，测试也检查了这一点。在两种哈希、有无周期的情况下各取 20,000 个随机点比较，Value 与 Perlin 的最大误差都小于 10⁻¹²。
- **格点**：Value Noise 在格点上等于格点的值；Perlin Noise 在格点上精确为 0，梯度等于格点的梯度向量。
- **导数**：解析导数与中心差分一致；缓和函数的一阶、二阶导数与数值导数一致。
- **连续性**：跨过格线时，值总是连续的；f′ 只有 linear 跳变；f″ 只有 quintic 连续。
- **范围**：Value Noise 不超出四个角的值的范围；Perlin 不超过 √2/2，4096 种梯度组合逐一检查，并且确实能取到 √2/2。
- **周期与种子**：置换表周期 256；指定周期时无缝平铺，包括跨过 0 的负坐标；整数哈希没有 256 的周期；同一种子结果相同，不同种子的相关系数小于 0.05。
- **哈希质量**：两种哈希的梯度编号都通过卡方检验，横向、对角、反对角相邻格点不相关。

我还故意改坏了 13 处代码，检查测试能否发现。第一轮有两处没被发现：

- **负坐标取模写错**（`-r` 代替 `r + period`）：原来的平铺测试只用了正坐标。补上跨过 0 的测试后可以发现。
- **置换表换一种混合方式**（`p[(p[x] + y) & 255] ^ p[y]`）：补上置换表的哈希质量检查后仍然通过。它其实是另一个同样合格的哈希，不是错误。

为了确认哈希质量检查真的能抓到坏哈希，又试了只查一次表的 `p[(x + y) & 255]`：反对角相关性检查发现了它。最终 13 处里 12 处被发现，剩下 1 处是等价的写法。

## 常见陷阱

| 问题 | 原因 | 解决 |
|---|---|---|
| 地形有明显的网格折痕 | 用了 linear 插值 | 用 smoothstep 或 quintic |
| 光照下沿格线有细微的亮暗线 | smoothstep 的二阶导数跳变 | 用 quintic |
| 很多山顶、谷底排列在网格上 | Value Noise 的格点梯度为 0 | 改用 Perlin；或者叠加多层旋转、偏移过的噪声 |
| 打光后坡面沿横竖方向排列 | Value Noise 的梯度在格线附近只剩一个分量 | 改用 Perlin |
| Perlin 噪声显得很平，阈值很难触发 | 实际范围远小于 [−1, 1] | 按实测分布缩放；99% 的值在 ±0.47 内 |
| 世界每 256 格重复一次 | 置换表只取坐标低 8 位 | 用整数哈希；或者让各层噪声用不同的偏移 |
| 平铺纹理在原点附近接缝错位 | 负数取模得到负值 | 取模后小于 0 时加上周期 |
| 走得很远后地形变成台阶 | float 坐标的精度不够 | double；或者区块编号用整数、区块内偏移用 float |
| 所有地图看起来都一样 | 种子没有参与哈希 | 把种子混入哈希；不同用途（高度、湿度）用不同种子 |
| 每帧重算整张噪声图很慢 | 没有缓存 | 噪声是确定的：按区块生成一次后缓存 |

## 练习

1. **一维与三维**：写出一维和三维的 Perlin 噪声。三维版本可以用 z 作为时间，得到连续变化的二维动画（云、火焰）。三维的理论上限是多少？用穷举验证。
2. **更多梯度**：把 8 个梯度换成 4 个（只有对角）或 256 个（均匀分布在圆上），重新测量分布、"方向性"相关系数和开销。
3. **区块坐标**：设计一个接口 `perlin(chunkX, chunkY, localX, localY)`，在坐标达到 10⁷ 时仍然没有台阶。用本文的精度测试验证。
4. **用导数做事**：用解析梯度生成一张"坡度图"，把坡度大于某个值的地方标成岩石。和用有限差分求坡度相比，速度差多少？
5. **域扭曲**：用一个噪声的值去偏移另一个噪声的坐标：`noise(x + k·noise(x, y), y + k·noise(x + 5.2, y + 1.3))`。观察 k 从 0 增大时图案怎样变化。
