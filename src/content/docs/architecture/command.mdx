**命令模式**把"做一件事"变成一个对象：按下跳跃键不是直接调用 `player.jump()`，而是生成一个"跳跃"命令，交给游戏去执行。多了这一层间接，就能做很多事：

- **录像**：把命令按时间记下来，重新执行一遍就是回放；
- **撤销**：每个命令记住怎样回到执行之前；
- **网络同步**：只发送命令，让每台机器各自执行（6.5 节的帧同步）；
- **改键、AI 控制**：输入设备和 AI 生成同样的命令，游戏不需要知道是谁发的。

本章用两个例子：一个可以录像回放的物理小游戏，一个可以撤销的瓦片编辑器。

## 录像：只存输入

游戏的一帧是一个函数：新状态 = step(旧状态, 这一帧的输入)。如果 step 是**确定性**的（同样的输入永远得到同样的输出），那么录像只需要存初始状态（或者一个随机种子）和每一帧的输入，回放就是从头再模拟一遍。

<CppSnippet file="architecture/command/command.h" region="sim" />

确定性的要求比看上去严格：

- **固定步长**：每帧的 dt 必须相同（0.1 节的固定时间步长）。用真实的帧间隔做 dt，回放时帧间隔不同，结果就不同；
- **运算顺序固定**：球与球的碰撞按 (i, j) 的固定顺序处理。用 `unordered_map` 遍历、多线程处理，顺序都可能变；
- **随机数只来自模拟自己的生成器**，并且是状态的一部分。渲染、音效、粒子用的随机数要用另一个生成器，否则"开不开粒子特效"都会改变回放；
- **状态哈希**：回放结束时比较状态的哈希，逐位相同才算对。

输入大多数时候不变（一直按着方向键），用游程编码（值，重复次数）存放：

<CppSnippet file="architecture/command/command.h" region="record" />

一小时、60 fps（21.6 万帧）、40 个球，输入平均每 1/3 秒变化一次：

| 存什么 | 大小 |
|---|---|
| 每帧的输入（3 字节） | 633 KB |
| 输入，游程编码 | **49 KB** |
| 每帧的完整状态（660 字节） | 136 MB |
| 每帧的完整状态，200 个球 | 663 MB |
| 每帧的完整状态，1000 个球 | 3.2 GB |

**存输入比存状态小 2800 倍**（136 MB 对 49 KB），而且和场景的复杂程度无关：1000 个球，输入还是 49 KB。格斗游戏、RTS 的录像文件只有几十 KB，就是这个原因。

### 混沌：差一点点就完全不同

确定性之所以必须"逐位相同"，是因为大多数游戏的模拟是**混沌**的：两个球碰撞时，碰撞角度的微小差别会改变它们弹开的方向，接着改变它们下一次碰到谁。

<Demo name="replay" title="录像回放与混沌" label="图 6.3a" caption="墨色实心是原始的一局：推杆由自动驾驶控制，每一帧的输入被录下来。朱红空心是回放：从同一个种子出发，逐帧喂入录下的输入。exact：两局逐位相同，空心圆一直套在实心圆上，状态哈希相同。1 ulp：回放开始时，把一个球的 x 改成相邻的下一个 float（差 0.00003 像素）。右边是两局里最远的一对球的距离（对数坐标），几乎是一条直线：差距大约每 20 帧放大 10 倍，两秒多以后两局完全不同。1e-3 px 只是起点高一点，同样的斜率。" />

在第 0 帧把一个球的 x 改动 ε，两局里最远的一对球多少帧后相差超过 1 像素、超过一个球的半径（9 像素）：

| 扰动 ε | 超过 1 px | 超过 9 px |
|---|---|---|
| 1 px | 23 | 34 |
| 0.1 px | 48 | 74 |
| 0.01 px | 75 | 89 |
| 0.001 px | 94 | 109 |
| 0.0001 px | 118 | 125 |
| 1 ulp（约 0.00003 px） | **131** | **138** |
| 10⁻⁵、10⁻⁶ px | 不分歧 | 不分歧 |

- **扰动每缩小 10 倍，只多撑 20～25 帧**：误差按指数增长（混沌系统的特征，增长率叫李雅普诺夫指数）。
- **一个 float 的最小差别（1 ulp），两秒多就变成肉眼可见的不同**。所以回放不能"差不多对"：任何一处运算顺序、编译选项、CPU 指令的不同，都会在几秒内变成完全不同的结果。
- 有意思的是 ε = 10⁻⁵ 和 10⁻⁶：它们比 x 附近的 float 间隔（约 3×10⁻⁵）的一半还小，加上去之后舍入回原来的值，两局完全相同。
- 跨平台、跨编译器的确定性（比如 x86 和 ARM 的回放互通）更难：编译器可能把 `a * b + c` 合并成一条乘加指令（结果的舍入不同），`sin`、`exp` 在不同的数学库里结果可能差一个 ulp（`sqrt` 不会，IEEE 754 要求它正确舍入）。[6.4 节](/architecture/fixed-point/)实测发现，本章的模拟在本机默认编译和网页版里的结果就不同，并用定点数解决这个问题。

### 跳转：关键帧

拖动回放的进度条，从头模拟到第 n 帧太慢。每隔 K 帧存一份完整状态（关键帧），跳转时读最近的关键帧，再模拟剩下的不到 K 帧：

<CppSnippet file="architecture/command/command.h" region="seek" />

一小时的录像，一步模拟约 0.5 微秒，随机跳转 200 次：

| 关键帧间隔 K | 关键帧数 | 内存 | 平均跳转 | 最慢 |
|---|---|---|---|---|
| 1 | 216 001 | 136 MB | 0.002 ms | 0.004 ms |
| 10 | 21 601 | 13.6 MB | 0.002 ms | 0.005 ms |
| 60（1 秒） | 3 601 | **2.3 MB** | **0.016 ms** | 0.33 ms |
| 600（10 秒） | 361 | 0.24 MB | 0.15 ms | 0.60 ms |
| 3600（1 分钟） | 61 | 0.04 MB | 0.79 ms | 1.9 ms |
| 36000（10 分钟） | 7 | 0.005 MB | 7.9 ms | 17.7 ms |

- **每秒一个关键帧（K = 60）只要 2.3 MB，跳转在 0.02 ms 内**。每分钟一个（K = 3600）不到 0.1 MB，跳转平均 0.8 ms，仍然在一帧之内。
- 内存和跳转时间成反比，K 的选择取决于一步模拟有多贵：这里 40 个球很便宜；如果一步要 1 ms（复杂的物理），K = 3600 意味着跳转要 1.8 秒。
- 测试验证了跳转结果和从头回放**逐位相同**，而且模拟的帧数恰好是 n mod K。

## 撤销：三种做法

编辑器的撤销是命令模式最经典的用途。在瓦片编辑器里画一笔（一次拖动），改变一组格子。怎样才能回到画之前？

1. **命令记住旧值**：这一笔改了哪些格子、每个格子原来是什么。撤销时把旧值写回去；
2. **每一步存完整快照**：撤销时把整个网格换回上一份；
3. **只存命令，每隔 K 步存一个检查点**：撤销时回到最近的检查点，重新执行到上一步。

<CppSnippet file="architecture/command/command.h" region="undo" />

**合并**：一次拖动里，鼠标经过的格子会被画到很多次（来回拖、停在原地）。同一个格子在一笔里只需要记一次最早的旧值。另外，一次拖动是一条命令，而不是每个格子一条：撤销一下就撤掉整笔。

<Demo name="undo" title="撤销与重做：瓦片编辑器" label="图 6.3b" caption="在网格上拖动画画（四种颜色），undo、redo 撤销和重做。右侧是历史：每条是一条命令（这一笔改了几个格子、占多少字节），箭头是当前位置，下面灰色的条目可以重做。一开始预先画了五笔、撤销了两笔，所以有两条灰色的。撤销之后再画一笔，灰色的重做分支就被丢弃了。关掉 merge，每个格子成为一条命令，一笔要撤销几十次。底部是同样的历史在三种做法下各要多少内存。" />

256×256 的地图（64 KB），2000 笔，每笔约 60 次绘制：

| 做法 | 内存 | 每次撤销 |
|---|---|---|
| 命令记旧值 | **373 KB** | 0.031 μs |
| 命令记旧值，不合并重复的格子 | 703 KB | — |
| 每步完整快照 | 125 MB | 7.4 μs |
| 只存命令，每 16 步一个检查点 | 9 002 KB | 1.4 μs |
| 只存命令，每 128 步一个检查点 | 1 962 KB | 3.3 μs |

- **命令记旧值比完整快照省 343 倍内存**，撤销也快 240 倍：只改 60 个格子，而不是复制 64 KB。
- **合并重复的格子省了一半**：一笔 60 次绘制，平均只有一半是不同的格子。
- 检查点 + 重放介于两者之间。它的优点是命令不需要知道怎样撤销自己，适合"撤销逻辑很难写"的操作（比如一个复杂的地形生成步骤）。
- 新的修改让**重做分支作废**：撤销三步后画了一笔，原来那三步就再也回不去了。这是几乎所有编辑器的行为；想保留所有分支，需要"撤销树"（Vim、Emacs 有）。

### 用反向操作撤销？

另一种常见的写法是：命令不存旧值，而是执行一个反向操作，"移动 +30"的撤销是"移动 −30"，"旋转 θ"的撤销是"旋转 −θ"。很多人担心浮点误差会让它越撤越偏。实测：

| 操作 | 重复次数 | 反向操作的误差 | 存旧值的误差 |
|---|---|---|---|
| 旋转 0.1 rad，再旋转 −0.1 rad | 1 | 7.6×10⁻⁶ px | 0 |
| 同上 | 1 000 | 1.1×10⁻⁴ px | 0 |
| 同上 | 1 000 000 | 1.1×10⁻⁴ px | 0 |
| 每次随机角度 | 1 000 | 2.1×10⁻⁵ px | 0 |
| 每次随机角度 | 1 000 000 | 1.7×10⁻³ px | 0 |
| 从 x = 90 右移 30，墙在 x = 100 | 1 | **20 px**（回到 70） | 0 |

**浮点误差其实很小**：旋转、反旋转一百万次，100 像素外的点只偏了千分之二像素；固定角度时误差甚至停在 10⁻⁴ 不再增长（数值落进了一个循环）。

**真正的问题是不可逆的操作**：物体在 x = 90，向右移动 30，被 x = 100 的墙挡住，停在 100。反向操作"向左移动 30"把它送到 70，而不是原来的 90。同样不可逆的还有：钳制到范围内、删除一个对象（反向操作"重新创建"需要知道它所有的属性）、整数除法、"设为最大值"。存旧值对所有操作都正确，所以是更稳妥的默认做法。

<Aside type="caution" title="关于时间">
本章的时间在 Apple M3 上测得，第一次完整测量时机器负载约 13，第二次升到 40（同时运行着其他程序）。大小、帧数这些与负载无关的数字两次完全相同；时间取负载较低的那一次。跳转时间与理论值一致：平均要模拟 K/2 步，每步 0.5 微秒，K = 3600 时约 0.9 ms。
</Aside>

## 测试

`command_test.cpp`：

- **回放**：三个种子各 3000 帧，两次回放的状态哈希相同；游程编码可逆，且压缩到原来的 1/5 以下；改变一秒的输入、少模拟一帧，哈希都不同。
- **跳转**：关键帧间隔 1、7、60、500，各随机跳转 30 次，结果与从头回放逐位相同，模拟的帧数恰好是 n mod K。
- **混沌**：初始位置差 10⁻⁴ 像素，在 3000 帧内差距超过一个球的半径（实测第 135 帧）。
- **撤销**：4000 次随机的画、撤销、重做（一笔里经常重复画同一格），三种做法与参照（每一步的完整副本）逐格比对；撤销后再画，重做分支作废。
- **合并**：同一格在一笔里画 10 次只存一条记录，撤销恢复到画之前的值，重做恢复到最后一次的值。

变异测试：故意改坏 16 处，第一轮发现 14 处（其中一处原本写成了编译不过的样子，换成"撤销不移动栈顶"后被发现）。漏掉的 2 处：

- **状态哈希漏掉了帧号**：原来的测试里，"少模拟一帧"时球的位置也不同，所以发现不了。但帧号决定了下一次随机冲量在什么时候发生，是状态的一部分。补上"只有帧号不同的两个状态，哈希也不同"。
- **模拟的随机数用完不前进**：每次随机冲量都打在同一个球的同一个方向上，回放照样逐位相同，测试发现不了。补上"每次使用后随机数状态都不同"。

补上后 16 处全部被发现。

## 常见陷阱

| 现象 | 原因 | 解决 |
|---|---|---|
| 回放几秒后就不对了 | 用了可变的 dt | 固定步长；渲染插值（0.1 节） |
| 开关特效后回放不同 | 特效和模拟共用一个随机数生成器 | 模拟用独立的生成器，并存进状态 |
| 不同机器上回放不同 | 编译器的乘加合并、数学库的差异、遍历顺序 | 固定编译选项；定点数（6.4 节）；只用有序容器 |
| 回放偶尔对、偶尔错 | 读了未初始化的变量；按指针地址排序 | 状态全部初始化；用稳定的编号排序 |
| 回放出错但不知道从哪一帧开始 | 只在结尾比较 | 每 N 帧记录一次状态哈希，二分定位第一帧不同的地方 |
| 拖动进度条卡顿 | 从头模拟 | 关键帧 |
| 撤销后状态不对 | 反向操作不可逆（钳制、删除） | 存旧值 |
| 撤销一次只撤掉一个格子 | 每个格子一条命令 | 一次拖动合并成一条命令 |
| 编辑器内存越用越多 | 每步存完整快照 | 存差异（旧值）；限制历史长度 |

## 练习

1. **定位分歧**：回放每 60 帧记录一次状态哈希。给一段出错的回放，用二分法找出第一个哈希不同的帧，再逐帧比较是哪个球先不同。
2. **差异快照**：关键帧不存完整状态，只存和上一个关键帧不同的字段。对 40 个球的模拟，能省多少？跳转会慢多少？
3. **撤销 + 选择**：编辑器里撤销"移动选中的物体"时，选择本身要不要恢复？Photoshop、Blender、VS Code 各是怎么做的？
4. **撤销树**：重做分支不丢弃，而是保留成一棵树，可以在分支之间切换。用怎样的数据结构？
5. **可变速回放**：0.5 倍、2 倍、倒放。倒放怎么实现（提示：关键帧 + 正向模拟一段，再倒序显示）？
